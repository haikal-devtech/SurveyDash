# Route map

20 October update: home is a compact Pengelola Survei/Surveyor choice. Subscription navigation, the workspace plan card, membership and billing tiles are removed. `/pricing` temporarily redirects to `/`; `/studio/settings/membership` and `/studio/settings/billing` temporarily redirect to `/studio/settings`. Pricing is omitted from the sitemap. These old routes are compatibility redirects, not active plan/billing pages. Internal usage accounting and optional server quotas are retained; no payment agreement or customer data is changed. Older route descriptions below are historical where they mention membership or billing.

Public routes: `/`, `/features`, `/pricing`, `/help`, `/contact`, `/privacy`, `/terms`, `/login`, `/forgot-password`, `/reset-password`, `/surveys`, `/f/[token]`, surveyor referral form `/r/[token]`, opt-in presentation viewer `/p/[token]`, `/robots.txt`, `/sitemap.xml`. Home distinguishes Pengelola Survei and Surveyor through `/login?role=manager` and `/login?role=surveyor`; the server determines the account's role after login. Recovery pages are excluded from indexing; reset pages use no-referrer/no-store headers and require a valid Better Auth token.

Owned workspace routes: `/studio`, `/studio/surveys`, `/studio/templates`, `/studio/search`, `/studio/import`, `/studio/[id]`, `/studio/[id]/presentations/[presentationId]`, `/studio/cleaning`, `/studio/[id]/cleaning`, `/studio/settings`, and settings subpages `account`, `workspace`, `membership`, `billing`.

All workspace routes require a Better Auth session and Pengelola Survei role. Survey, template, presentation and image queries also constrain `owner_id`; guessing a resource ID does not grant access. Surveyor accounts cannot gain workspace access by changing the selected-workspace cookie. Anonymous form access is controlled independently by token, publication status and visibility. Archived and trashed surveys stop accepting responses.

Surveyor routes: `/surveyor` and `/surveyor/profile` require the signed-in Surveyor role. `/api/surveyor` returns the actual account's masked profile and active assignments; `/api/surveyor/profile` updates that account's profile. Assignment questions are read-only and omit option score values and respondent rows. `/api/account/context` returns the actual signed-in role and destination, regardless of selected workspace.

Manager directory `/studio/surveyors` shows assigned surveyors only in the selected owned workspace and offers survey-specific invitations. Entry points are visible in the sidebar, manager overview and survey editor. Owned `/api/surveys/[id]/surveyor-invitation` reads/creates a seven-day invitation or revokes it. `/invite/surveyor/[token]` exposes only the survey title/institution before joining; `/api/surveyor/invitations/[token]/accept` requires a completed Surveyor account and a valid active invitation. Acceptance is idempotent. Disabling an invitation leaves existing assignments intact; disabling an assignment cannot be undone by that surveyor accepting an invitation. Login carries a bounded invitation token through either authentication mode and redirects only to the fixed invitation route.

Pengelola assignment API `/api/surveys/[id]/surveyors` lists, creates, revokes, or reactivates assignments within the owned survey. Public POST `/api/referrals/[token]` validates the active referral and stores its attribution with a response. Reactivation rotates the token; a browser-supplied surveyor ID cannot replace the server source. Direct `/f/[token]` links remain unattributed. Owned response pages and CSV include immutable source snapshots.

Owned `/api/surveys/[id]/cleaning` serves paginated review candidates, saves explicit question mapping, and records review decisions with the actual actor. Matching is restricted to the same survey and mapped name/bank/account fields or substantive answer patterns. Review flags do not delete responses or exclude them from analysis. See [Surveyor workflow](SURVEYDASH_SURVEYOR_WORKFLOW.md) and [privacy operations](SURVEYDASH_SURVEYOR_PRIVACY.md) for access, encryption, and retention limits.

APIs: auth `/api/auth/[...all]`; owned surveys `/api/surveys`, `/api/surveys/[id]`, `/manage`, explicit demo `/api/surveys/demo`; public form `/api/forms/[token]`; template CRUD `/api/templates`, `/api/templates/[id]`, `/apply`; slide documents `/api/presentations`, `/api/presentations/[id]`, `/template`; images `/api/assets`, `/api/assets/[id]`; workspace `/api/workspace`; Google resource JSON import `/api/import/forms`.

Presentation sharing: owned `/api/presentations/[id]/share` supports status, reviewed publication and revocation. Anonymous `/api/shared/[token]` returns only a frozen slide snapshot; `/api/shared/[token]/assets/[id]` serves only images referenced by that snapshot. The viewer is excluded from indexing and uses no-store/no-referrer headers. Archive and survey trash revoke links; restoring does not reactivate them. Editor-team administration endpoints remain unavailable; surveyor assignment is a separate restricted role.

Explicit platform admin: `/studio/admin` and `/api/admin/workspaces`. Only designated platform-admin account IDs with the Pengelola role can list or select other workspaces. Normal owners retain full features in their own isolated workspace. Surveyor accounts are excluded from selectable workspaces. Account profile routes always refer to the signed-in user.

Revision APIs: `/api/surveys/[id]/responses` returns a bounded server page or streamed CSV (`format=csv`); `/api/surveys/[id]/insights` returns statistical summaries, with capped text samples only when `samples=true`. `/api/surveys/[id]?view=metadata` omits submissions/audit; the default response remains compatible with older clients. All three use selected-workspace ownership.

`/api/account/avatar` uploads and serves private profile images for the actual logged-in user. `/api/integrations/google-forms` reads connection status, starts OAuth, previews an authorized Form or disconnects local credentials. `/api/integrations/google-forms/callback` validates the owner, encrypted state and PKCE exchange. Mutations check the request origin; provider configuration is required. Admin workspace selection does not change Google/profile identity.
