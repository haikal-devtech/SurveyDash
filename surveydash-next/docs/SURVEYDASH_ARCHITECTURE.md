# Architecture

Surveyor follow-up on `codex/surveyor-workflow`: assigned read-only collection is a separate role and portal, with encrypted payout profiles, immutable referral attribution and owner-scoped manual cleaning review. Existing accounts remain managers; shared team editing is still deferred. See `SURVEYDASH_SURVEYOR_WORKFLOW.md` for schema, routes, key management, testing and release gates.

Next.js 16 App Router, React 19, TypeScript, Tailwind CSS, Radix dialogs, TanStack Table and Recharts. Better Auth handles email/password sessions; the attached brief's Auth.js assumption did not match the existing implementation, so authentication was preserved.

Production uses Prisma Postgres through `pg` in Singapore. SQLite is the development/test fallback. Preview deployments must use `STAGING_DATABASE_URL`; missing staging configuration fails closed. They never fall back to the production database. Local staging uses an ignored `.env.staging.local` with the same cloud staging database.

Tables retain their existing data: `surveys`, `submissions`, `audit`, `templates`, Better Auth tables and rate limits. Additive tables include `workspace_settings`, `presentations`, `presentation_assets`, `presentation_shares` and `google_form_connections`. Survey metadata and versioned presentation documents are JSON stored as TEXT. No response or authentication table was replaced. A composite submission index supports survey/date pagination.

Responses preserve question snapshots, stable option IDs, optimistic revisions and idempotency keys. SKM uses exactly nine scored elements and per-element valid-answer denominators. Missing answers are not converted to a score of one. Corrections append audit entries. All mutations check sessions, origins, ownership and payload limits. Optional quotas use an owner transaction lock, apply to opening forms and accepting new responses, and retain existing data.

Templates support form, one-page presentation layout and complete survey packages. Slide templates additionally store `slidePreset`: design, image references and source-question bindings. Derived chart counts and bound metric text are removed before saving. Reuse creates a new document with new element/slide IDs, maps compatible destination questions and recalculates from destination responses. Manual text/images remain intentionally reusable; users are asked to review personal information.

Slide rendering uses a shared DOM renderer for canvas, preview and exports. Data binding refresh replaces only bound numbers/distributions and preserves manual edits and layout. Saves reject stale versions and inaccessible assets. Uploaded PNG/JPG/WebP images are bounded, decoded with Sharp, normalized to WebP and stored durably in the owned database. SVG and animated uploads are rejected.

PDF and PowerPoint export use the same 16:9 slide renderer at 1920 × 1080 pixels. PPTX contains one slide image per page; its individual text/chart components are not editable in PowerPoint. The Studio source document remains editable. PDF pages also contain images, so text search and screen-reader text extraction are not supported in these exports.

Public presentation links are explicit and private by default. Publication locks the owned document, verifies its version and requires review acknowledgment. A 192-bit random capability refers to a frozen snapshot containing only title, slides, simulation label, publication date and source version. Question bindings and owner/survey metadata are removed; charts must use choice, checkbox or rating sources. Manual text and images are included after the owner’s review. Only snapshot images can be fetched through the token. Republishing updates the reviewed snapshot; revocation followed by publication rotates the token. Archive and survey trash revoke access transactionally, and restoring leaves it revoked. The loaded viewer checks every 15 seconds and on visibility changes; previously downloaded/captured copies cannot be recalled.

Google import accepts the official resource Form JSON shape, validates supported question types and requires acknowledgment of unsupported items. The optional official OAuth connector requests only `forms.body.readonly`, uses PKCE and an owner-bound encrypted state cookie, and fetches a form by editor link/ID. It does not import responses, scrape Google or alter the original form. AES-256-GCM credentials remain on the server, bound to the authenticated account, with a key derived from the session secret. Disconnect deletes the local credentials; Google consent can be revoked separately. Changing the session secret requires reconnecting Google. Provider credentials and consent configuration are external prerequisites.

The Data tab fetches up to 100 rows per request (15 by default), with parameterized server filtering and sorting. Option labels remain separate from stored IDs; literal searches do not interpret SQL wildcards. CSV streams all filtered rows in batches of 100 using the requested order. Concurrent edits/submissions can change a multi-batch CSV while it is generated; exports are not historical snapshots. Insights reuse the existing statistical functions on server-loaded responses and are fetched lazily. Default insights omit free-text samples; the one-page dashboard explicitly requests at most 50 recent samples per field, shortened to 500 characters. Server analytics still have linear memory cost and require further work for very large datasets.

SMTP recovery is enabled only by an explicit flag and complete configuration. Nodemailer enforces TLS for remote/production SMTP hosts. Better Auth reset tokens expire after 30 minutes, are single-use, and revoke existing sessions. Next.js `after` keeps delivery tasks alive after the generic public response. Request rate limiting uses the database. Missing SMTP configuration keeps recovery unavailable in the UI. The delivery path has been tested against an actual local SMTP capture, not a production mailbox.

Profile uploads reuse validated, normalized, durable owned image storage; the avatar endpoint returns a private no-store 128px WebP. Account profiles and Google credentials use the actual logged-in identity. Explicit platform administrators are stored by immutable account ID in `platform_admins`. Workspace owners may invite other managers with an expiring link. An HttpOnly context cookie is validated against an active `workspace_members` record or platform-admin grant on every request; unauthorized selections resolve to the caller's own workspace. Shared objects keep the original owner and audited corrections retain the actual editor. Only the owner or a platform admin may manage workspace invitations and memberships. Payment checkout remains deferred. See `SURVEYDASH_WORKSPACE_TEAM.md` for acceptance/revocation rules and the separate private admin map of registered surveyor provinces.
