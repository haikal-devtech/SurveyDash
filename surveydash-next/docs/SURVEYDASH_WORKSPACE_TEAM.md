# Shared workspaces and surveyor registration provinces

Surveyor registration now requires a canonical province on the first account step. The same field can be updated in the private profile. It is stored independently from encrypted payout information and from per-survey assignment territory. Legacy profiles remain readable with a null province; no location is inferred. Failed account creation removes both an uncreated profile and its province row atomically. New/updated surveyor consent uses notice version `2026-10-23-surveyor-v2`.

Platform admins open **Admin workspace → Peta surveyor**, including the direct route `/studio/admin?view=surveyors`. The directory contains all surveyors with actual auth accounts, including unassigned people; it excludes unfinished/orphan registrations. Province counts follow the declared profile province. The directory/API are guarded by platform-admin authorization and return only user ID, username, full name and province, without email or payout fields. Unknown legacy provinces remain **Belum diisi**. The map supports hover/focus numbers, persistent selection, filtering and 30-second visible-page refresh. It reuses the same small province canvas and CC BY 4.0 geometry as the task map; task response/target semantics are unchanged.

Workspace owners use **Pengaturan → Workspace → Pengelola workspace** to create a seven-day invitation link. An authenticated manager must explicitly accept the link; surveyor accounts cannot accept it. The public invitation reveals only workspace name and expiry, while the acceptance screen describes access to surveys, responses and presentations. Login/registration preserves a validated workspace-invitation token and returns to that fixed route. No messages or emails are sent automatically.

Accepted managers can switch between their own workspace and workspaces they have joined. The effective owner remains the original workspace owner; shared surveys/assets/templates/presentations are not copied or reassigned. Existing repository ownership checks scope all reads and writes to that selected owner. A workspace cookie only selects a context: each request resolves it against current membership or an explicit platform-admin grant. An unrelated/removed selection falls back to the caller's own workspace, so requests for the former workspace's object IDs are rejected. Answer corrections and existing assignment/target mutations retain the actual authenticated actor.

Only the owner or an explicit platform admin may list/manage members or issue/revoke a workspace invitation. Ordinary members cannot grant further access. Link revocation prevents future joins without removing current members. Member revocation removes future workspace access without deleting stored work. A revoked member cannot use an old or newly rotated generic invite to rejoin; the owner must explicitly reactivate that membership. Existing platform-admin workspace switching is preserved. Workspace access does not confer platform-admin rights or access to private surveyor payout data.

The additive tables are `surveyor_home_provinces` (profile FK and province), `workspace_members` (owner/user composite key, active state, inviting/updating actor and timestamps), and `workspace_invitations` (one high-entropy current token per owner, active state and expiry). Invitation acceptance/revocation and member changes use the same owner advisory transaction lock in PostgreSQL; SQLite uses the existing transaction queue. Cloud backup discovers the tables automatically; staging restore includes them after users/profiles. Apply the additive schema before releasing code that queries it. Older releases remain compatible. Do not infer or backfill real provinces or memberships during deployment.

Additional tests verify that SQLite signup writes join Better Auth's existing transaction and that a failed local transaction start cannot roll back an externally owned transaction.
